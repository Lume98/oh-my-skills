# commit-zh

> 为已暂存的 Git 改动生成高质量中文提交信息并执行提交。用于用户要求“帮我提交”“生成 commit message”“按最佳实践提交暂存文件”等场景，或任何需要对 `git add` 后的改动进行规范化中文提交的任务。

## Commit Zh

按下面流程完成提交，不要跳步。

## Workflow

1. 检查是否存在暂存改动。
- 运行 `git diff --cached --name-only`。
- 若为空，明确告知“当前没有已暂存文件”，并给出下一步：先 `git add <file>`。

2. 审阅暂存差异并提炼变更意图。
- 运行 `git diff --cached`，总结“做了什么”和“为什么”。
- 重点识别：功能新增、缺陷修复、重构、文档、测试、构建/配置。

3. 生成中文提交信息。
- 使用中文，简洁、可读、可追溯。
- 推荐格式：`<类型>: <摘要>`。
- 常用类型：`feat`、`fix`、`refactor`、`docs`、`test`、`build`、`chore`、`perf`、`style`。
- 摘要使用动宾短语，聚焦结果，不写空话。
- 单行优先，建议不超过 50 个中文字符（含英文/符号时按可读性调整）。
- 避免包含 AI、工具或生成过程描述。

4. 执行提交。
- 使用 `git commit -m "<中文提交信息>"`。
- 若提交失败，先读错误并处理常见问题（如用户名邮箱未配置、无暂存改动、钩子失败），然后反馈可执行修复步骤。

5. 返回结果。
- 输出最终提交信息和提交结果摘要（如 commit hash 与变更文件数）。

## Message Quality Bar

- 准确：与暂存改动强一致，不泛化。
- 完整：必要时体现范围或模块。
- 稳定：同类改动使用一致类型前缀。
- 简洁：不堆砌细节，不复制 diff。

## Examples

- `feat: 新增供应商列表分页与关键词筛选`
- `fix: 修复代理配置保存后未即时生效的问题`
- `refactor: 拆分 provider 设置面板并统一表单状态管理`
- `docs: 补充本地开发与 tauri 构建说明`
